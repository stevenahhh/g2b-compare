# WEB APPLICATION BOUNDARY

## OVERVIEW

`app.py:create_app` composes the priority catalog, estimate, data, search,
sync, live-diagnostic, API, health, and frontend surfaces.

## ROUTING CONTRACT

- Production defaults to the Svelte SPA when no test reader/database override is injected.
- `CORE_SPA_PATHS` map only `/`, `/data`, `/estimates`, and estimate detail paths to SPA HTML.
- `/api/*`, exports, health, assets, and legacy `/live`, `/priority`, `/sync` routes
  must never fall through to SPA HTML.
- Injected `SearchReader` apps retain the legacy template route used by focused tests.
- `/healthz` and `/livez` report process liveness; `/readyz` depends on catalog data.
- Populated local runs enter through `scripts/start.py --home .g2b` or
  `g2b-compare --home .g2b serve`; both resolve `.g2b/g2b.sqlite3`.

## CONVENTIONS

- Route modules translate HTTP input/output; services own use cases and stores/readers own SQL.
- Keep API models in `api_models.py` and response status/error shapes stable.
- `frontend_dist/` is generated by `frontend/vite.config.js` and packaged by Hatch.
- `app.py` deliberately fails if the production SPA index, worker, assets directory,
  or referenced boot assets are missing.
- Legacy `templates/` and `static/` remain supported surfaces until callers/tests are removed.
- Preserve local search behavior; the live router is a diagnostic exception, not the default.
- Keep product links evidence-backed; do not synthesize unsupported detail URLs.

## ANTI-PATTERNS

- Never hand-edit `frontend_dist/index.html`, hashed assets, or `sw.js`.
- Never add a catch-all route that converts API/legacy 404s into SPA 200 responses.
- Never make liveness depend on provider network calls or expensive readiness work.
- Never use direct `uvicorn g2b_compare.web.app:app` to validate populated local data;
  its module-level fallback resolves `data/g2b-compare.sqlite3`.
- Never query SQLite directly from a route when a service/store boundary exists.
- Never expose provider exception text or the service key in HTTP responses.

